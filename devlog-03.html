拡張機能編 & フロントエンド着手

2026-09-19

第三弾の概要

第三弾は「店舗・スタッフ管理システム」。スタッフ側の運用を支えるバックエンドとして、 Phase単位で機能を積み上げました。

  • Phase 3-1(MVP)：スタッフログイン(4桁PIN)、当日予約×4レーンのダッシュボード、 来店受付のチェックイン/アウト、レーン稼働状況の管理(故障即時ブロック)、 教室出席管理(グループ単位)、決済確認
  • Phase 3-2：レーンアサイン変更、キャンセル対応、修了生フラグ、売上管理
  • Phase 3-3：メンテナンス管理

料金体系はゲーム数ではなく時間単位課金。教室は全5回のカリキュラム (基本投球→ストライク→スペア→復習→卒業記録会)で、当日開放ロジックのような複雑な自動化は 最終的に見送り、「締切ベースの自動開放」+スタッフの手動運用でシンプルに保つ方針に 落ち着きました。バックエンドはここまでで完成し、残タスクはフロントエンドのみという状態でした。

拡張機能①②③④の流れ

第三弾には4つの拡張機能があり、優先順位は ④→③→②→① の順で進めました。

  • ④ 個人カルテ×グループ出欠管理：第三弾(グループ出欠)と第四弾(会員個人データ)は 別アプリ・別DBなので自動連携せず、「教室を修了して一般ボウラーになった」という事実だけを持つ ClassCompletionRecord に最小化して実装
  • ③ レーンアサイン自動化×達成バッジ・称号：会員側の AchievementBadge を実装。 店舗側の自動化は結局「締切ベース自動開放」に統合する形に整理し、同時チェックイン時の排他制御も 「小規模運用ならスタッフの目視判断で十分」という結論で見送り
  • ② コーチシフト管理：Instructor モデルを新設し、 教室のコース/回への担当インストラクター割当として実装
  • ① 店舗側メンテナンス管理×会員側オイル抜きリマインド：唯一、既存スタックと分けて FastAPI + PostgreSQL + Docker + AWS という新スタックで学習目的からゼロ構築。 EC2デプロイまで完走し、第三弾・第四弾との双方向API連携(故障検知→自動登録、整備完了→会員のマイギア履歴反映)も 実機確認済みで完了

4項目とも、途中でセッション切れによるコード消失や既存バグの発見など紆余曲折はありましたが、 GitHubへの反映まで完了しています。

今日のフロントエンド着手〜4画面完成

第三弾はここまでバックエンド中心だったため、今日はいよいよ第三弾のReactフロントエンドに着手しました。

  • フォルダは bowling-lane-management-frontend(バックエンドとは別リポジトリ)
  • Vite + React + ESLint、axios・recharts・react-router-domを導入
  • 実装順序は スタッフログイン(4桁PIN)→ホーム画面(ボタン式メニュー)→当日予約ダッシュボード→ 来店受付→教室出席管理 の5画面構成のうち、4画面を実装完了(すべてダミーデータで動作確認済み)
  • 予約ダッシュボードの各予約項目に「受付へ」ボタンを追加し、URLパラメータ(lane・name)で 来店受付画面に値を渡す連携も実装済み

半日でここまで進んだのは、拡張①・第五弾で積んできたReact構築の経験が効いた形です。
